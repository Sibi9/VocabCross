# VocabCross — محرّك لعبة مفردات البكالوريا الجزائرية

لعبة مفردات إنجليزية لطلبة السنة الثالثة ثانوي (الشعب العلمية)، مبنية بالكامل بلغة **C++17** ومكتبة **Raylib**، بواجهة بورتريه **540×960**، وبيانات المنهاج الرسمية في `assets/data/bac_vocabulary.json`.

> **ملاحظة تصميمية مهمة:** جميع العناصر التفاعلية (الأزرار، العقد، النجوم، الأقفال، شبكة الكلمات، الحروف، شريط القلم، الإطار الأكاديمي، العجلة، ونافذة التعريب) تُرسم برمجياً داخل المحرك. لا يُحمّل المحرك أي صورة واجهة جاهزة من `assets/reference_ui` إطلاقاً. خلفيات الجزر الثلاث هي مشاهد بيئية فقط تم تنظيفها من كل HUD/عقدة/نص عبر `tools/make_clean_backdrops.py`، وتُستخدم كخلفية بيئية مع رسم كل الواجهات فوقها.

## 1. المحتوى والوحدات

| الوحدة | الموضوع | عدد المراحل |
| :--- | :--- | :---: |
| Unit 1 | Ethics in Business — الأخلاق في المعاملات | 10 |
| Unit 2 | Safety First — الأمن الغذائي وسلامة المستهلك | 8 |
| Unit 3 | Astronomy and the Solar System — الفلك والفضاء | 8 |
| Unit 4 | Feelings and Humor — المشاعر والفكاهة | 6 |
| **المجموع** | | **32** |

كل مرحلة مرتبطة بكلمة، تعريف إنجليزي، مرادف، تعريب عربي، مستوى تكرار في البكالوريا، ونمط لعب:

- `crossword`: **كلمات متقاطعة حقيقية** من 2–3 كلمات متقاطعة من نفس الوحدة؛ كل خانات الشبكة قابلة للتعبئة، وكل الخانات جزء من كلمة. الكلمة الهدف + كلمات مرافقة لها تعريفاتها من JSON. تُحلّ جميع الكلمات للفوز.
- `image`: تخمين الصورة + إطار أكاديمي + لوحة مفاتيح كريمية.
- `wheel`: **شبكة كلمات حقيقية من كلمتين متقاطعتين**؛ كل خاناتها قابلة للتعبئة. تسحب/تنقر حروف العجلة لتكوين إحدى الكلمتين، وعند مطابقتها تُملأ خاناتها تلقائياً. تُحلّ الكلمتان للفوز.

## 2. البناء والتشغيل

```bat
build.bat
run_game.bat
```

أو مباشرة:

```powershell
.\VocabCross.exe
```

المتطلبات: Visual Studio C++ Build Tools (MSVC x64) وملفات `lib/raylib.lib` الموجودة في المشروع. لا يحتاج Build إلى Flutter أو Web.

### أوضاع الاختبار

```powershell
# اختبار ذاتي شامل: 4 وحدات، 32 مرحلة، بناء 32 شبكة كلمات متقاطعة، مطابقة 13 كلمة عجلة، التعريب
.\VocabCross.exe --self-test

# التقاط 12 صورة حقيقية من المحرك إلى verification_screenshots/
.\VocabCross.exe --verify-ui

# تدقيق الكود + مقارنة بصرية + فحص الديناميكية + فحص العربية
py verify_and_compare.py

# اختبار نقر/كتابة فعلي: Crossword + Image Guess + فتح شاشة العجلة
powershell -ExecutionPolicy Bypass -File tools/interactive_test.ps1

# تشغيل مرحلة محددة مباشرة (لتجربة نمط معين)
.\VocabCross.exe --word ECLIPSE
.\VocabCross.exe --word BRIBERY
.\VocabCross.exe --word GALAXY
```

نتائج التدقيق: `verification_reports/` (لوحات `compare_*.png`، `overview.png`، `summary.json`، `audit_log.txt`).

## 3. التحكم

> **ملاءمة النافذة والإدخال:** اللعبة 540×960؛ إذا كانت الشاشة أصغر (مثل 1600×900) تُصغَّر النافذة تلقائياً مع الحفاظ على النسبة 9:16 وتُضاف أشرطة سوداء عند الحاجة. `include/input.hpp` يحوّل إحداثيات الفأرة من نافذة النظام إلى إحداثيات اللوحة 540×960، لذلك تعمل الأزرار والسحب حتى بعد تغيير حجم النافذة. يمكن اختبار ذلك بـ`tools/interactive_test.ps1`.

| الإجراء | الطريقة |
| :--- | :--- |
| اختيار مرحلة من الخريطة | النقر على عقدة مفتوحة |
| تبديل الجزيرة | سهمَا الشريط العلوي، أو زر الخريطة أسفل اليمين |
| Crossword | اختر الكلمة من شرائح `1·7` / `2·7` أعلى لوحة التعريف؛ انقر كرة حرف لتعبئة الخانة النشطة؛ انقر خانة مملوءة لحذف حرفها؛ كل الكلمات مطلوبة للفوز |
| Image Guess | النقر على المفاتيح لإدخال الحروف؛ زر `⌫` أو النقر على خانة للحذف؛ `NEED A HINT?` للتلميح |
| Wheel | **اسحب** بين الحروف أو **انقر متسلسلاً**؛ الخط يبقى متصلاً حتى بين الحروف (يتحول للأحمر إن كانت البادئة خاطئة) ولا يُمسح إلا عند الإفلات. إذا طابقت كلمة كاملة تُملأ خاناتها. `CLEAR` للمسح |
| Victory Modal | `NEXT LEVEL` أو `ISLAND MAP` |
| الإعدادات | زر الترس (الصوت، تصفير التقدم) |

## 5. التعريب العربي

- `ArabicShaper::reshape` يطبّق:
  - اختيار الشكل الصحيح (منفصل/ابتدائي/وسطي/نهائي).
  - دمج لام-ألف.
  - تجميع الحركات مع الحرف الأساسي.
  - ترتيب بصري RTL مع عزل المقاطع اللاتينية والأرقام.
  - عكس الأقواس في السياق العربي.
- **لماذا Tahoma وليس Cairo؟** Raylib 5 لا يطبّق OpenType GSUB. لذلك نرسم أشكال العرض (Presentation Forms-B) مباشرة. `Cairo.ttf` ينقصه 33 شكلاً من الأشكال المطلوبة (تم فحصه بـ `tools/check_arabic_font.py`)، بينما `tahoma.ttf` يغطي كل الأشكال الـ154. النتيجة: تعريب متصل وصحيح 100% بدلاً من مربعات `.notdef`. (ملف Cairo محفوظ في المشروع للرجوع، لكن المحرك يستخدم Tahoma لأن Raylib لا يملك محرك تشكيل GSUB.)

## 6. مكافحة الغش

- لا يوجد في `include/` أو `src/` أي تحميل لـ `assets/reference_ui/...`.
- الصور البيئية `clean_ethics.png` / `clean_safety.png` / `clean_space.png` نتجت عن إزالة **كل** العقد والأرقام والنجوم والأقفال والـHUD والنصوص بواسطة أقنعة + inpainting (`tools/make_clean_backdrops.py`)، ثم تُرسم فوقها كل العناصر التفاعلية برمجياً.
- كل الأزرار والبطاقات والنجوم والأقفال والحروف والعجلة والإطار ونافذة الفوز مرسومة عبر طبقات Raylib (ظل، حافة 3D، تدرج، إطار مزدوج، لمعة).
- `--verify-ui` يلتقط من داخل المحرك (RenderTexture ثم ExportImage)، وليس من ملفات مرجعية.
- فحص الديناميكية يقارن مرحلتين مختلفتين لكل نمط، ويفشل السكربت إذا كانت الصور متطابقة.

## 7. ملاحظات وحدود معروفة

- خلفيات الجزر الثلاث مشاهد بيئية مشتقة من الصور المرجعية بعد تنظيفها؛ الواجهات فوقها برمجية بالكامل. هذا مسموح صراحة في خطة العمل (Clean Matte Environment Backdrop).
- شاشات Crossword/Image Guess/Wheel تستخدم مشاهد برمجية أصلية 100%، لذا تختلف درجات التشابه اللوني/الرسمي عن الصور المرجعية (المولدة بالذكاء الاصطناعي) رغم تطابق التخطيط والوظائف.
- شاشة العجلة لا تحتوي على إطار هاتف أو يد بشرية (بحسب الخطة)؛ مرجعها الأصلي يحتوي عليهما، لذلك لا تُقارن الحواف.
- خريطة Safety First تعرض 8 عقد لأن بيانات الوحدة الثانية 8 كلمات، بينما الصورة المرجعية تعرض 10 عقد.
- خريطة المشاعر (الوحدة الرابعة) جزيرة أصلية مرسومة برمجياً، وليست مستخرجة من صورة مرجعية.
